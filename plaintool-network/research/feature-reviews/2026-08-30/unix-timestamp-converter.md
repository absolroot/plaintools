# Unix timestamp converter

- 리뷰 일자: `2026-08-30`
- 라우트: `/[locale]/unix-timestamp-converter/`
- 기능/코어/QA: `apps/web/src/features/time/`, `packages/time-core/`, `scripts/qa/time_feature.py`
- 공개 상태: `indexable`, 17개 로케일
- 검토 기준: 커밋 `02a7c57`과 현재 통합 작업트리

## 이미 개선된 점

| 개선 | 사용자 가치 | 근거 |
| --- | --- | --- |
| timestamp→날짜와 날짜→timestamp를 한 작업면의 명시적 모드로 분리 | 한 화면에서 두 입력 의도가 경쟁하지 않으며 현재 모드가 분명하다 | `TimeConverter.astro`의 `data-mode-button`, `client.ts`의 모드별 실행 |
| 초/밀리초 자동 감지에서 11~12자리 값을 추측하지 않고 오류로 처리 | 잘못된 단위 추측으로 전혀 다른 날짜를 보여주는 위험을 줄인다 | `detectTimestampUnit()`, `index.test.ts`의 ambiguous-unit 테스트 |
| IANA 시간대, 로컬 시간대, 고정 UTC 오프셋을 지원 | 서버 로그와 현지 시각을 같은 instant 기준으로 비교할 수 있다 | `Temporal`, `Intl.supportedValuesOf`, 고정 오프셋 목록 |
| DST 누락 시간과 반복 시간을 구분하고 earlier/later를 명시적으로 선택 | 서머타임 경계에서 조용히 한쪽으로 보정하지 않는다 | `dateToTimestamp()`와 DST gap/repeat 테스트 |
| 음수 epoch, 소수 초, 2038 경계 경고 | 1970년 이전 값과 고정밀 로그를 다루고 32비트 위험을 알 수 있다 | `secondsToNanoseconds()`, `y2038Warning` 테스트 |
| 결과별 복사와 비동기 복사 권한 검증 | 입력이 바뀐 뒤 오래된 복사 완료 메시지가 나타나지 않는다 | `client.ts`의 `revision`/값 재확인 |
| 입력을 브라우저 메모리에서 처리하고 URL·스토리지로 보내지 않음 | 민감한 로그 시각이 주소/기록에 남지 않는다 | `ARCHITECTURE.md`, time client/core에 전송·저장 경로 없음 |

## 경쟁 도구에서 확인한 점

| 경쟁 도구 | 확인된 기능 | 확인 일자 | 직접 URL |
| --- | --- | --- | --- |
| Epoch Converter | 초·밀리초·마이크로초·나노초, 현재 epoch, 양방향 변환, 기간 변환, 연/월/일 시작·끝, 다수 언어 코드 예시 | 2026-08-30 | https://www.epochconverter.com/ |
| epoch.to | timestamp/날짜 문자열 자동 감지, 최대 나노초 정밀도, UTC 기준 오늘 시작·끝, URL shortcut | 2026-08-30 | https://epoch.to/ |

경쟁 사이트의 기능 표시는 해당 페이지에서 관찰한 범위다. 지속적인 로컬 처리,
정확도, 접근성, 전체 시간대/DST 동작을 상호 벤치마크한 결과는 아니다.

## 상대 평가

### 더 나은 점

- DST gap과 repeated local time을 서로 다른 오류로 설명하고, 보정 방향을
  사용자가 선택하도록 만든 점은 단순 변환기보다 진단성이 높다.
- 11~12자리 정수의 단위를 조용히 추정하지 않는 정책과 2038 경고가 있다.
- URL shortcut을 제공하지 않는 대신 입력값을 URL에 넣지 않는 경계가 명확하다.
- 17개 로케일의 오류·가이드·FAQ까지 같은 공개 계약에 포함된다.

### 비슷한 점

- 양방향 epoch/date 변환, 현재 시각 입력, UTC/로컬 표현, 복사 가능한 결과는
  주요 전문 변환기와 기능 축이 겹친다.
- 브라우저에서 JavaScript로 처리한다는 사실만으로 경쟁 우위라고 할 수는 없다.

### 부족한 점

- 일부 전문 로그에서 쓰는 마이크로초/나노초 정수 단위를 직접 선택하지 않는다.
  이는 경쟁 기능 격차지만 현재 일반 사용자 흐름에 반드시 필요한 결함은 아니다.
- 여러 timestamp 일괄 변환, 기간 계산, 연/월/일 경계 계산, 코드 예시가 없다.
- timestamp 입력 후 즉시 변환되지 않고 Convert 버튼을 눌러야 한다.
- 여러 시간대를 나란히 비교하는 보기는 없다.
