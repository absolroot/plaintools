# 기능 옵션과 기본값 원칙

이 문서는 기능 경쟁력 리뷰에서 발견한 후보를 실제 제품에 넣을지 판단하는
공통 UX 기준이다. 경쟁 도구에 기능이 있다는 사실만으로 PlainTool에 추가하지 않는다.

## 기본 원칙

1. 사용자는 옵션을 열지 않아도 가장 일반적인 작업을 안전하게 끝낼 수 있어야 한다.
2. 기본 활성화는 되돌릴 수 있고, 의미 손실 가능성이 낮으며, 대다수 사용자가
   기대하는 동작에만 허용한다.
3. 원문 의미를 바꾸거나 결과 범위를 넓히는 동작은 기본 off로 두고, 실행 전에
   영향이 드러나야 한다.
4. 구현상 필요한 최적화와 안전장치는 옵션으로 노출하지 않고 자동 적용한다.
5. 낮은 빈도의 전문 작업은 접힌 옵션보다 별도 route가 더 적합한지 먼저 판단한다.
6. 기능 수가 아니라 기본 경로의 성공률, 결과 이해도, 복사·다운로드까지의
   마찰 감소를 개선 기준으로 삼는다.

## 노출 단계

| 단계 | 사용 조건 | UI 원칙 | 예시 |
| --- | --- | --- | --- |
| 자동 적용 | 모든 사용자에게 안전하고 설명이 필요 없는 동작 | 설정을 만들지 않는다 | stale Worker 차단, streaming, locale-aware casing |
| 기본 활성화 | 일반적으로 기대되며 손실 위험이 낮은 동작 | 필요할 때만 해제 가능 | license comment 보존, 안전한 Base64 복구와 복구 사실 표시 |
| 고급 옵션 | 특정 작업에 유용하지만 의미나 출력이 바뀌는 동작 | 기본 off, 접힌 Options에 영향 설명 | 반복 디코드, diff ignore, JSON sort keys, NBSP 변환 |
| 별도 기능/보류 | 주 작업 흐름과 입력·결과 구조가 달라지는 동작 | 같은 화면에 넣지 않는다 | IPv6/VLSM, batch 변환, 전문 QR payload, 코드 에디터 |

## 기본값 판정 질문

다음 질문에 모두 `예`일 때만 기본 활성화를 고려한다.

- 사용자의 명시적 선택 없이 실행해도 원문 의미를 바꾸지 않는가?
- 실패하거나 잘못 추정해도 원문과 이전 결과를 잃지 않는가?
- 일반 사용자의 다수 작업에 실제로 적용되는가?
- 결과에서 적용 사실과 영향을 짧게 설명할 수 있는가?
- 17개 locale과 RTL에서도 같은 의미를 유지하는가?

하나라도 `아니오`라면 기본 off, 별도 모드, 또는 보류로 분류한다.

## 2026-08-30 백로그 재분류

| 기능 | 조정된 판정 | 이유 |
| --- | --- | --- |
| AI text cleaner bidi/NBSP | 기본 off 또는 보수적 safe preset | 합법적인 RTL 방향과 non-breaking spacing 의미를 바꿀 수 있다 |
| Base64 반복 디코드 | 기본 off 고급 옵션; 1단계 결과 보존 | 예상보다 깊은 해석은 일반 decode의 기본 동작이 아니다 |
| JWT `NOT VERIFIED` | 항상 표시 | 옵션이 아니라 결과 신뢰 경계다 |
| JavaScript license comments | 기본 보존 | 법적 고지를 조용히 삭제하는 것보다 안전하다 |
| Hash expected checksum | 기본 화면의 선택 입력 | 기존 작업을 방해하지 않고 핵심 검증 작업을 완성한다 |
| Base64 byte 수/잘림 표시 | 항상 표시 | 선택지를 늘리지 않고 결과 이해도를 높인다 |
| IP 결과 행별 복사 | 항상 제공 | 계산 의미를 바꾸지 않는 직접 행동이다 |
| JSON tree/search | 결과 보기 전환으로 검토 | 변환 옵션이 아니라 긴 결과를 읽는 보조 보기다 |
| Text Compare ignore 규칙 | 기본 off 고급 옵션 | 차이를 의도적으로 숨기므로 기본값이 될 수 없다 |
| Data Converter BOM/줄바꿈 | 기본값 유지, 호환이 필요할 때만 고급 옵션 | 대상 시스템에 따라 정답이 달라진다 |
| Word Counter 문장 수/읽기 시간 | 우선순위 하향; 실제 수요 확인 후 보조 Details | WPM·문장 경계 가정이 필요하고 핵심 카운트에는 필수가 아니다 |
| Timestamp micro/nanoseconds | 보류 | 일반 사용 빈도 대비 단위 선택과 결과 복잡도가 크다 |
| Timestamp 다중 시간대 | 선택한 추가 시간대 1개부터 수요 검증 | 2~4개 고정 비교 UI는 기본 화면을 과밀하게 만든다 |
| QR structured payload | 수요별 별도 mode/route 검토 | Wi-Fi·vCard 등은 입력 구조가 일반 텍스트와 다르다 |
| IPv6/VLSM | 별도 기능으로만 검토 | IPv4 계산기의 옵션으로 넣기에는 입력과 결과 개념이 다르다 |
| large-file streaming | 자동 적용 | 사용자가 선택할 성격이 아닌 구현 품질 개선이다 |

## 기본 화면에 남길 것

- 입력
- 결과
- 가장 중요한 모드 하나 또는 명확한 양방향 전환
- 복사·다운로드·초기화 같은 직접 행동
- 오류, 자동 복구, 손실·신뢰 경계

그 밖의 후보는 기본 화면에 추가하기 전에 이 문서의 판정 질문을 통과해야 한다.
