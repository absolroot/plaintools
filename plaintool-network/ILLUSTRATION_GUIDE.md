# AbsolTools tool illustration system

The user-provided 35-image reference archive on 2026-10-24 defines this system. The source PNGs and their checksums are kept locally at `research/design/icon-shape-references-2026-10-24/`; they are excluded from Git and the public site. Their repeated features are a restricted purple palette, simple filled geometry, and deliberate negative space. The reference artwork is not copied into shipped icons.

## Visual grammar

- Use a 128 × 128 SVG artboard. Keep the principal silhouette inside an approximately 8–120 unit safe area and optically center it at the final displayed size.
- Keep the nine featured icons' vertical gradient, from lavender `#BF96FA` to violet `#8673F3`. Compact directory icons use two flat tones: subject `#B692F5` and action/result `#725BE8`. Use the darker tone to clarify an operation or output, not as decoration. A strong one-piece symbol can remain single-tone. Do not assign category colors, shadows, white paint, or glowing highlights.
- Build icons from one dominant filled shape plus, when necessary, one operation cue. Use transparent cutouts to describe a photo, document, number, code structure, or QR matrix. Let the card surface show through the cutout in both themes.
- Use a consistent 8-unit construction grid for repeated blocks, lines, rays, arrows, and QR modules; use 4-unit adjustments only for optical positioning and curves. Repeated parts must have identical dimensions and regular gaps. Use a small consistent object radius when the depicted object needs it; the UI cards remain square.
- Draw image thumbnails as actual squares. Resize can show different square sizes, but neither thumbnail may be stretched into a rectangle. Every two-sided format conversion, including PDF ↔ image and data format conversion, uses equal square input and result tiles. Keep the cutout image inside each tile so the square boundary remains visible.
- Related tools share an object silhouette but differ in the operation. A merge icon must visibly contain multiple inputs; compression must have a clear inward motion. Do not let a generic plus, sparkle, or check carry the entire meaning.
- Keep text out of icons unless a short file type or numeral is necessary for recognition at 56 px. `PDF` and `123` may be used as transparent cutouts after rendered-size review. Adobe's Acrobat/PDF mark is not a generic product icon for this project.

## Reference traits to preserve

The folder/zip and selection-frame examples use equal square notches on a stable grid. The crop, arrow, and transform examples communicate one operation with large orthogonal shapes. The photo, camera, and sun examples use a single immediately recognizable silhouette. The document examples align their interior bars to one edge and a steady rhythm. The overlapping-object example keeps the back and front forms separate without an outline. The later references add bold single-purpose signs: a down arrow, hidden eye, attachment, calendar, send arrow, and calculator. Their circles, diagonals, and rectangular holes remain simple at small sizes. These traits matter more than reproducing any one example's exact path.

The [official iLoveIMG Korean directory](https://www.iloveimg.com/ko) was inspected on 2026-10-24 at 1440 px. Its compact icons put one clear operation in each card: inward arrows for compression, a photo plus expansion cue for resizing, scissors for cropping, and two format sheets for conversion. Related conversion routes reuse a visual grammar and rely on the adjacent label for the exact formats. AbsolTools adopts the single-operation clarity and related-tool family resemblance while retaining its own purple material, flat card grid, and three-column desktop directory.

## Compact directory marks

The 40 px directory slot displays its illustration at 40 px. At that size, prefer a bold silhouette and one 8-unit or larger operation cue. Avoid thin strokes, tiny repeated marks, detailed document text, and small badges. Paired data icons use equal 64 × 64 square tiles, with the lighter source above and left of the darker result. Their ordering and tone express direction without a tiny connector arrow. Each tile contains one large cue: four cells for CSV, M for Markdown, braces for JSON, or angle brackets for HTML. Base64 shows one large B64 label with a right arrow below for encode and a left arrow below for decode. URL encoding keeps URL/percent tiles and JWT decoding keeps token segments/braces. The card label states the full task name. The 49 image-format conversion routes share a light source tile with a large down-right action arrow and a dark result tile with a recognizable photo; the card label states each source and target format. Image resizing uses a large image moving toward a smaller one, while upscaling uses an outward arrow from an image. Crop/rotate/skew is represented by a solid square with a substantial transparent scissors silhouette as its primary action. Related operations must remain distinguishable at the rendered size. The nine featured illustrations remain larger and more specific.

Edit `scripts/generate-tool-illustrations.py` and run `python scripts/generate-tool-illustrations.py` to regenerate the compact assets. The script contains the hand specified geometry and two-tone palette; the SVG files under `apps/web/public/illustrations/tools/` are its outputs. Run `python -m unittest scripts.test_tool_illustration_geometry` to check the square-tile contract. Update `tool-illustrations.test.ts` only when the route-to-asset contract changes.

## Acceptance check

Render all affected icons together on the actual home cards at 64 px desktop, 50 px mobile, and 40 px in directory cards. Inspect light, dark, and RTL layouts. At the final size, the subject and operation must remain distinct without relying on fine detail. Check the 128 × 128 viewBox, intrinsic dimensions, equal module sizes, transparent cutouts, local loading, no remote resources, and no page overflow. Save a browser screenshot; source geometry alone does not establish quality.
